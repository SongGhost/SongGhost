### Confirmed Root Cause Context
- `lore_facts` (`src/lib/db/schema.ts:157-166`) is keyed by `artistId` / `trackId` / `albumId` — opaque text ids with **no name columns and no artists/albums/tracks table to join to**.
- The live YouTube dial queue (`StationTrack` in `src/data/stations.ts`) carries artist **name** + `isrc` + `itunesTrackId` + `spotifyId`, but **not** the `artistId` that `lore_facts` uses. So `getUnservedLoreFact` can never match the playing track on the dial, and every lore clip falls back to the broadest "any unserved" bucket (or `null` → `STRICT_TRUTH_GUARDRAIL`).
- `artistName` already flows end-to-end today: the queue has it, `dj-intro` sends it in the request body (`src/lib/dj-intro.ts:229`), and `/api/generate-script` already receives it. The only missing piece is that `lore_facts` has no `artistName` column and `getUnservedLoreFact` does not accept one.
